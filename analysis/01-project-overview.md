# Paperclip 项目概览

## 1. 核心愿景

Paperclip 是自主经济的基础设施 -- 为 AI Agent 公司提供控制平面（Control Plane），使其具备结构化治理、任务管理、成本控制和人类监督能力。

**一句话总结：** Paperclip 是 AI Agent 公司的操作系统，让自主运营的 AI 公司具备可治理、可追踪、可扩展的能力。

---

## 2. V1 实现范围与边界

### 2.1 V1 做什么

| 领域 | 具体内容 |
|------|----------|
| 公司管理 | 公司生命周期（创建/列表/获取/更新/归档），多公司数据模型 |
| 目标体系 | 层级化目标管理，关联公司使命 |
| Agent 管理 | Agent 生命周期、组织结构（汇报树）、适配器配置 |
| 任务管理 | 层级化任务（Issue）、父子关系、评论、原子化签出（atomic checkout） |
| 治理审批 | 董事会审批招聘新 Agent 和 CEO 战略提案 |
| 心跳运行 | 心跳调度、状态跟踪、取消机制 |
| 成本追踪 | 成本事件采集和多维度汇总（Agent/任务/项目/公司） |
| 预算控制 | 预算设置、软告警（80%）和硬限制（100% 自动暂停） |
| Web UI | 仪表盘、组织架构图、任务看板、审批页面、成本页面 |
| Agent API | 任务读写、心跳上报、成本上报的 Agent 接口 |
| 审计日志 | 所有变更操作的 activity_log 记录 |
| 公司可移植包 | 公司配置的导出/导入（JSON manifest + Markdown 文件） |

### 2.2 V1 不做什么

| 明确排除的功能 | 说明 |
|----------------|------|
| 插件框架 | 不提供第三方扩展 SDK |
| 收入/支出核算 | 仅追踪 Token/LLM 成本，不追踪外部收支 |
| 知识库 | 不在核心系统中，未来作为插件 |
| 公共市场 (ClipHub) | 不提供公共模板市场 |
| 多人董事会 | V1 仅支持单人操作 |
| 自动恢复编排 | 不自动重新分配或重试任务 |
| 实时传输优化 | 不支持 SSE/WebSocket（使用轮询） |

## 3. 六大核心概念及职责

### 3.1 Company（公司）

公司是 Paperclip 的一等实体，所有业务数据都以公司为作用域。一个 Paperclip 实例可运行多个公司。公司包含目标、Agent 员工、组织结构、预算和任务层级。公司状态包括：`active`、`paused`、`archived`。

### 3.2 Agent（智能体/员工）

Agent 是公司的 AI 员工。每个 Agent 具有：
- **身份信息**：名称、角色、职称、能力描述
- **组织位置**：向谁汇报（`reports_to`），严格树形结构
- **适配器配置**：`process`（本地进程）或 `http`（HTTP 回调），定义 Agent 如何被调用
- **预算**：月度预算和已花费金额
- **状态机**：`idle -> running -> idle/error`，支持 `paused` 和不可逆的 `terminated`

Agent 不运行在 Paperclip 内部，而是在外部运行并通过 API 向控制平面汇报。

### 3.3 Issue（任务/工单）

Issue 是核心工作单元，替代传统任务概念。特点：
- **层级结构**：支持父子关系，所有任务最终可追溯到公司目标
- **单一受理人**：一个任务只能分配给一个 Agent
- **原子化签出**：通过数据库级原子操作防止并发冲突（失败返回 409）
- **状态流转**：`backlog -> todo -> in_progress -> in_review -> done`，支持 `blocked` 和 `cancelled`
- **沟通渠道**：Agent 间通过任务评论沟通，没有独立的聊天系统

### 3.4 Heartbeat（心跳系统）

心跳是 Paperclip 调度 Agent 执行的协议机制：
- **调度器**：按 Agent 配置的间隔触发心跳
- **适配器接口**：`invoke()`（启动）、`status()`（查询）、`cancel()`（取消）
- **上下文投递**：`thin`（仅发送 ID，Agent 自行获取上下文）或 `fat`（携带完整上下文）
- **运行记录**：每次心跳产生 `heartbeat_runs` 记录，追踪状态、日志、退出码

### 3.5 Approval（审批/治理）

审批是人类董事会监督 AI 公司运营的关键机制：
- **招聘审批**（`hire_agent`）：Agent 或董事会发起，需董事会批准后才能创建新 Agent
- **CEO 战略审批**（`approve_ceo_strategy`）：CEO 提交战略计划，董事会审核后才能开始执行
- **董事会权限**：随时暂停/恢复任何 Agent、重新分配任务、修改预算、覆盖任何决策

### 3.6 Cost Event（成本事件）

成本追踪系统负责监控 Token/LLM 使用成本：
- **多维归因**：按 Agent、任务、项目、目标、公司汇总
- **预算层级**：公司月度预算 -> Agent 月度预算 -> 可选项目预算
- **硬限制执行**：达到 100% 预算时自动暂停 Agent，阻止新的签出和调用
- **计费代码**（`billing_code`）：支持跨团队成本归因

## 4. 关键技术约束和设计原则

### 4.1 技术栈

| 层 | 技术选型 |
|----|----------|
| 前端 | React + Vite |
| 后端 | TypeScript + Express REST API |
| 数据库 | PostgreSQL（Drizzle ORM） |
| 开发数据库 | PGlite 嵌入式（不设 DATABASE_URL 即自动使用） |
| 认证 | Better Auth（会话认证 + Agent API Key） |
| 文件存储 | 本地磁盘（`local_disk`）或 S3 兼容存储 |

### 4.2 架构约束

1. **Company-scoped 数据隔离**：所有业务实体必须绑定到公司，路由和服务层必须强制公司边界检查
2. **单租户部署、多公司数据模型**：一个实例 = 一个操作者的所有公司
3. **控制平面而非执行平面**：Paperclip 不运行 Agent，只编排调度它们
4. **单一受理人模型**：每个任务只能有一个 assignee，通过原子操作保证
5. **不自动恢复**：系统暴露问题而非静默修复，崩溃恢复靠人工处理
6. **审计一切**：所有变更操作写入 `activity_log`
7. **API Key 安全**：仅存储哈希值，明文仅在创建时显示一次
8. **Secret 管理**：敏感值不存储在 `adapter_config.env` 中，使用 secret 引用

### 4.3 设计原则（来自 SPEC.md）

1. **不限定 Agent 运行方式** -- 任何语言、框架、运行时均可
2. **公司是组织单位** -- 一切归属于公司
3. **任务是沟通渠道** -- 无独立消息系统，所有协作通过任务和评论
4. **所有工作追溯到目标** -- 层级任务管理，无孤立任务
5. **董事会治理** -- 人类保留最终控制权
6. **暴露问题而非隐藏** -- 良好的审计和可见性
7. **原子化所有权** -- 单一受理人 + 原子签出
8. **渐进式部署** -- 从本地一键启动到托管部署
9. **可扩展核心** -- 清晰边界为未来插件留空间

## 5. 部署模式

Paperclip 支持两种运行模式：

| 模式 | 说明 |
|------|------|
| `local_trusted` | 默认模式，单用户本地部署，无登录摩擦 |
| `authenticated` | 需要登录，支持私有网络和公共部署 |

### 开发环境

```bash
pnpm install
pnpm dev
# API 和 UI 均在 http://localhost:3100
# 留空 DATABASE_URL 自动使用嵌入式 PGlite
```

## 6. 与其他工具的集成方式

### 6.1 Agent 适配器集成

| 适配器类型 | 集成方式 | 说明 |
|-----------|----------|------|
| `process` | 子进程执行 | 启动本地命令（如 Claude Code、Python 脚本），通过 stdout/stderr 和退出码追踪状态 |
| `http` | HTTP 请求 | 向外部 Agent 发送 webhook/API 调用，2xx 表示接受，支持异步回调 |

### 6.2 Agent 认证集成

Agent 通过 Bearer API Key 认证 REST API。创建 Agent 时生成连接字符串（含服务器 URL + API Key + 说明），Agent 使用此 Key 调用控制平面 API 完成任务管理、心跳汇报、成本上报等操作。

### 6.3 Paperclip Skill

提供一个 SKILL.md 技能定义文件，教会 Agent 如何与 Paperclip API 交互。内容包括：
- 任务 CRUD
- 状态汇报
- 公司上下文读取
- 成本上报
- 跨 Agent 协作规则

此 Skill 与适配器类型无关，可加载到 Claude Code、注入到提示词中、或作为自定义 Agent 的 API 文档使用。

### 6.4 文件/资产存储

通过 `assets` 表管理文件元数据，支持两种存储后端：
- `local_disk`：本地文件系统（默认）
- `s3`：S3 兼容对象存储

### 6.5 公司可移植包

支持公司配置的导出/导入：
- 导出格式：`paperclip.manifest.json` + Agent Markdown 文件
- 导入模式：创建新公司 或 导入到现有公司
- 冲突策略：`rename`、`skip`、`replace`
- 支持预览（dry-run）
