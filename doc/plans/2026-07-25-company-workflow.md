# 公司工作流、实时研究与 PDF 交付

## 目标

将 Telegram、飞书中的正式任务按固定公司治理链执行：

1. 用户向 BitWorld 董秘下达任务。
2. 董秘受理并提交集团 CEO。
3. 集团 CEO 只向匹配的事业部 CEO 授权，不越级派职能 Agent。
4. 事业部 CEO 向全部启用的职能 Agent 分工，职能结果回到事业部 CEO 整合。
5. 董秘复核实际执行记录、实时来源和最终结论，交付聊天摘要与中文 PDF。

## 生产实现

- Cloudflare Workflows 持久化各角色阶段，并支持步骤重试。
- D1 保存工作流、步骤、来源、报告元数据和初期低流量 PDF BLOB。
- Browser Rendering 生成浅米白、传统红主题的 A4 中文 PDF。
- 报告下载使用随机令牌的 SHA-256 哈希校验，响应为 `private, no-store`。
- 市场任务使用 CoinPaprika、Kraken、OKX、DefiLlama 等实时源；趋势任务补充 Kraken 近 30 日日线。
- 统筹、拆解、研判与终稿优先使用 DeepSeek V4 Pro；基础数据职能使用 Flash，失败时按混合路由回退 Cloudflare Workers AI。

## 质量闸门

- 加密市场任务至少取得两个独立实时行情来源，否则中止。
- 事业部 CEO 的分工单必须覆盖全部本次职能 Agent。
- 当前日期只取系统受理/检索时间，不采用模型记忆。
- 终稿不得声称超过证据覆盖范围的历史窗口。
- 终稿中的 `0.x` 数值必须能按其展示精度与来源数值匹配。
- 已完成的职能 Agent 不得被写成缺席、遗漏或未履职。
- 区间高点不得写成历史高点；不同统计口径的成交额不得直接计算市场份额。

## 生产验收

- 验收任务：最近 TRX 市场趋势分析报告。
- 正式工作流：`9ada8403-6c9a-4067-b736-3fb2f03b84c3`。
- 实际链路：集团 CEO → 加密事业部 CEO → 数据/策略/风控 → 加密事业部 CEO → 董秘。
- 实时来源 5 条，包含 2026-06-25 至 2026-07-25 的 30 日日线。
- PDF 为 A4、10 页、640,012 字节；已验证下载响应、文件头、页数、封面、正文和来源页。
- 早期验收样本已标记为 `superseded`，其工作流改为失败状态，仅保留审计记录。
